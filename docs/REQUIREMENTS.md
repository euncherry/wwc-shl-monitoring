# 사용자 역할
시스템은 **관리자(Admin)** 와 **사용자(User)** 두 가지 역할로 구분됩니다.

| **구분** | **역할** | **데이터 범위** | **메뉴 구성** |
| --- | --- | --- | --- |
| **관리자** | 전체 텔레코일존과 히어링루프를 통합 운영 | 전체 기관·기기 | 대시보드, 히어링루프 관리, 텔레코일존 관리, 펌웨어 관리, 알림센터 |
| **사용자** | 소속 기관의 히어링루프를 모니터링 | 소속 기관의 기기만 | 대시보드, 히어링루프 관리, 정보관리, 기술 지원 |

## 핵심 개념

### 텔레코일존 = 기관

텔레코일존과 기관은 동일한 단위입니다. 역할에 따라 부르는 명칭이 다릅니다.

- **관리자** 시점 : 여러 기관을 관리하므로 **"텔레코일존"** 이라 부름
- **사용자** 시점 : 본인이 속한 하나의 기관이므로 **"우리 기관"** 이라 부름

### 별칭(alias) 시스템

히어링루프 기기에 사용자가 별칭(`alias`)을 부여할 수 있습니다.

- 별칭이 지정된 경우 : **별칭**이 메인 타이틀, MAC 주소가 서브 태그로 표시
- 별칭이 미지정인 경우 : **MAC 주소**가 메인 타이틀로 표시 (동일한 레이아웃)

# 관리자

## 히어링루프 관리
1. **히어링루프 등록( 기기 추가 )**
    1. 등록할 히어링루프 MAC주소 입력
2. **전체 히어링루프 리스트**
    - 개별 히어링루프 상세보기
        - **개별 히어링루프 상태 정보 보기**
            - **전원상태**
            - **기기 동작 여부**
            - 온도 (제어 x)
            - 볼륨 (제어 x)
            - **네트워크 정상 연결**
        - **개별 히어링루프 상세 정보 보기**
            - 펌웨어 버전
            - 배치된 텔레코일 존
            - MAC 주소
        - **기기 삭제**
        - **개별 히어링 루프 별칭 변경**

## 텔레코일존 관리
1. **텔리코일 존 등록**
    1. [ 텔레코일 존 이름 , 담당자 이메일 , 사용자 계정 생성] 입력
2. **전체 텔레코일존 카드 그리드 리스트**
3. **텔레코일별 상세보기**
    1. 담당자 이메일 수정
    2. 사용자 모드 계정 관리 (ID / PW 수정 및 조회)
    3. 배정된 히어링루프 목록 조회
    4. 히어링루프 추가 배정 및 삭제
    5. 알림 이력 확인
    6. 텔레코일존 삭제

## 펌웨어 관리
1. 펌웨어 추가
    1. [펌웨어 파일 , 펌웨어 버전 , 간단 설명] 입력
2. 펌웨어 업데이트
    1. 개별·전체 펌웨어 업데이트

## 알림센터
- KPI 카드 (전체 알림, 처리 대기, 긴급 알림, 오늘 발생)
- 처리 상태 탭 : 처리 대기 / 사용자에게 전달됨 / 관리자 종결 / 전체
- 유형 필터 (온도 이상, 전원 차단, 볼륨 이상, 연결 끊김, 펌웨어 업데이트 필요)
- 우선순위 필터 (긴급, 경고, 정보)
- 알림 상세 모달 (사용자에게 전달 / 무시·종결)
- 일괄 전달 및 일괄 종결
- 알림 설정 (온도·볼륨 임계값, 알림 그룹핑, 자동 에스컬레이션 시간)

## 구현 단계 분할 (2026-06-04 — 역할별)

도메인별이 아니라 **역할별**로 간다. 사용자 페이지는 관리자가 존+계정+기기 배정을 만들어야 로그인·데이터가 생기므로 **관리자 전체(3단계)를 끝낸 뒤 사용자(4단계)**. 각 sub 착수 전 질문. 대시보드 2개는 ⛔ 보류.

- **3단계 = 관리자 전체**: 3A 히어링루프 관리 → 3B 텔레코일존 관리 → 3C 펌웨어 관리 → 3D 알림센터(목) → 3E 관리자 대시보드(⛔보류)
- **4단계 = 사용자 전체**: 4A 히어링루프 관리 → 4B 정보관리 → 4C 기술지원(정적) → 4D 사용자 대시보드(⛔보류)
- 3A·3B까지가 "의미 있는 최소"(기기+존+계정).

상세 단계 표는 CLAUDE.md §14 참조.

## 3A — admin/hearing-loops 확정 결정 (2026-06-04)

`src/pages/admin/hearing-loops/index.tsx`는 원본(reference) 복사본이라 새 요구사항과 충돌. 아래로 확정. (디자인/마크업은 유지, 데이터·구조만 교체)

### 제거 (원본 잔재)
- **OTA 업데이트 탭 + 우측 "OTA 업데이트" 버튼 + 선택/전체 업데이트 + 체크박스 컬럼** — 펌웨어는 별도 "펌웨어 관리" 메뉴 소관.
- **"미배정 기기" 탭** — 미배정 기기 배정은 텔레코일존 관리(4단계)로 이동. (상단 탭 구조 자체가 사라져 단일 리스트가 됨)
- **상세 모달의 제어 요소** — 전원 토글 스위치, 볼륨 슬라이더, 하단 "변경사항 저장" 버튼 → 모두 **조회 전용**으로. (남는 액션: 별칭 저장, 기기 삭제)

### 변경
- **식별자** — friendly `device.id`(HL-식) 표기 제거. 타이틀 = `alias 있으면 alias(메인) + MAC(서브태그) / 없으면 MAC(메인)`. 검색은 **별칭·MAC** 기준(기존 "기기 ID, 텔레코일존, MAC" 문구 교체).
- **별칭** — 로컬 state → 실연동 `PATCH /devices/:mac { alias }`, **중복 409 처리**.

### 결정된 항목 (질문 답변)
1. **텔레코일존 필터 추가** — 상태 필터 옆에 존 선택 드롭다운 필터 추가(CLAUDE.md §11 일치).
2. **기기 등록 = 단건 + bulk** — MAC 단건(`POST /devices`) + 여러 개 한 번에(`POST /devices/bulk`, created/skipped 반환) 둘 다 지원.
3. **상세 모달 "알림 이력" = 목 유지** — 기기별 최근 알림 목록을 MSW 목으로 채워 표시(알림센터 자체는 5단계).
4. **목 값 = '목' 배지 표시** — 전원·네트워크·볼륨·펌웨어버전은 목이므로 값 옆에 **'목' 배지**를 달아 구분. 온도·동작은 실값(`last_temperature`/`last_gpio_state`)이라 배지 없음.
   - ⚠️ **TODO**: StatusReport 확장 배포 시 **MSW 핸들러 + '목' 배지 둘 다 제거** (CLAUDE.md §13에 기록).

### 데이터 출처 (Swagger 실스펙 대조 — 2026-06-04 보정)

**엔드포인트 (REAL, 스펙 존재)**
- 목록 `GET /devices` (배열 통째, 페이지네이션 없음) · 상세 `GET /devices/:mac`
- 등록 `POST /devices` `{ mac_address, zone_id?, alias? }` (**409 = MAC/별칭 중복**) · 일괄 `POST /devices/bulk` `{ devices:[…] }` → `{ created, skipped[] }`
- 삭제 `DELETE /devices/:id` (**키 = 숫자 id**) · 별칭 `PATCH /devices/:mac { alias }` (**409 = 별칭 중복**)
- 존 필터 옵션 `GET /zones`
- (이 페이지 미사용) 상태이력 `GET /devices/:mac/status`, 존배정 `PATCH /devices/:id/zone`

**`DeviceResponseDto`에서 바로 쓰는 실값 (REAL, 배지 없음)**
- `mac_address`, `alias`(nullable·unique), `zone`/`zone_id`(존 이름까지 옴), `last_temperature`(온도), `last_gpio_state`(동작), `registered_at`(등록일), `last_seen_at`(최근 업데이트), `id`(삭제·존배정 키)

**🟡 응답 DTO에 필드가 없어 목으로 병합 (+'목' 배지)**
- **전원(power)**, **네트워크(network)**, **볼륨(volume)**, **기기별 펌웨어 버전** — MSW로 device 응답에 필드 주입.
  - ⚠️ **TODO**: StatusReport 확장 배포 시 **MSW 핸들러 + '목' 배지 둘 다 제거**(CLAUDE.md §13).

**🟡 엔드포인트 자체가 없음 → 완전 목**
- 상세 모달 **'알림 이력'** — 이 Swagger에 `/alerts*`가 전무(알림센터 = 5단계 목).

**🟢 파생 (API 필드 아님 — FE가 계산)**
- 상태 뱃지 `normal/warning/error/offline` = `last_seen_at`(실값) + 온도·볼륨 등 + **목 임계값**으로 FE가 환산.
  - ⚠️ **백엔드 `status`(`PENDING`/`ACTIVE`)와 다름!** DTO의 `status`는 프로비저닝 상태(등록·연결 여부)일 뿐, 건강 뱃지가 아니다. **절대 그대로 색 뱃지에 쓰지 말 것.** 별도 파생 함수 필요.
  - 임계값(기본 5분 등) 미확정 → 백엔드가 `connection_status` 내려주면 파생 로직 제거(BACKEND §3).

### ⚠️ 백엔드 확인 필요 (4단계 존 배정 전)
- `PATCH /devices/:id/zone`에 **requestBody가 Swagger에 명세돼 있지 않음**(zone_id를 어디로 받는지 불명 — 문서 누락 의심). 이 페이지엔 영향 없으나 존 배정 구현(4단계) 전 백엔드에 확인.
